# さっきのタブ — MRU 0.3.0

Chrome 拡張だけで、今のウインドウで閲覧済みの直近8タブを、最近表示した順に切り替えます。Windows の Alt+Tab を参考に、中央のパネルにプレビューカードを横並びで表示します。ビルド・外部パッケージ・補助アプリは不要です。

## 読み込み用フォルダー

このリポジトリ内の `extension/` フォルダー

通常使用中の Chrome には読み込んでいません。今回増えた権限を含め、ユーザーが導入を決める必要があります。

## 操作

| 操作 | キー・方法 |
| --- | --- |
| 一覧を開く／開いている一覧を取消 | macOS: **Control + Q（⌃Q）** またはツールバーの拡張アイコン |
| 選択を進める | Tab / → / ↓ |
| 選択を戻す | Shift + Tab / ← / ↑ |
| 確定 | Enter / カードをクリック |
| 取消 | Esc / × / 背景をクリック |

フォーカス中ウインドウの現在タブを先頭に表示し、直前の閲覧済みタブを初期選択します。画像がなくても、閲覧済みならタイトルのカードを残します。巡回中は実タブを変えず、確定時だけ切り替えます。先頭・末尾は循環し、選択カードまで横スクロールします。Control を離しても確定しません。一覧は最大2分で閉じます。タブ1件でも操作できます。直前へ即切替する専用コマンドは削除しました。

## Ctrl + Tab の検証結果

[Chrome Commands 公式資料](https://developer.chrome.com/docs/extensions/reference/api/commands) の対応キーには Tab が含まれず、Chrome／OS の一部のショートカットが優先されます。macOS の `Ctrl` は Command に変換され、実際の Control を指定するには `MacCtrl` を使います。

隔離 Chrome **156.0.8078.48** で使い捨ての検証用拡張を読み込み、実際の `chrome.commands.getAll()` も調べました。

| manifest の指定 | Mac での登録結果 |
| --- | --- |
| `Ctrl+Tab` | `⌘⇥`（Command + Tab。要求された Control ではない） |
| `mac: MacCtrl+Tab` | shortcut が空文字（Control + Tab は割り当てられない） |
| 本拡張の `mac: MacCtrl+Q` | `⌃Q` |

したがって Control + Tab での起動は採用せず、代替の2キー Control + Q を使用します。Windows / Linux の初期キーは従来どおり **Ctrl + Shift + Y** で変更していません。「Tab を指定すると必ず manifest 読み込み自体が失敗する」という説明は、現行 Chrome の実測には当てはまりません。登録結果と実際の OS キー入力は別であり、物理キーからの起動・既存環境との競合はユーザーの環境で確認してください。ページの keydown を使って Chrome の標準 Ctrl+Tab を置き換える方式も実装していません。

## 表示位置と制限ページ

- 通常の HTTP / HTTPS ページ: ユーザーが起動した時だけスクリプトを注入し、HTML dialog をページのトップレイヤーに表示します。**Chrome のコンテンツ領域中央**です。OS 画面全体やブラウザーのツールバーを含めた中央ではありません。背景を暗くし、横カード・選択枠で Windows Alt+Tab の見た目に寄せています。OS の Alt+Tab そのものを再現するものではありません。
- `chrome://`、Chrome Web Store、PDF など注入できないページ: **拡張専用の小さな別ウインドウ**に同じカード UI を表示します。元 Chrome ウインドウの外枠中央を基準に位置を計算します。OS が移動・クランプする場合があります。ウインドウのタイトルバーが付き、元ページの背景は暗くしません。
- file / data / 他拡張ページも、この実装では別ウインドウ扱いです。ファイルアクセスの設定は要求しません。
- フォールバックはフォーカスを外しても閉じます。通常ページの一覧は元タブから別タブへ切り替えると閉じます。
- ライト／ダークは OS の設定に追従します。閉じたシャドウ DOM でページのスタイルから UI を分離し、listbox / option / aria-activedescendant とフォーカス管理を実装しています。

## プレビューの取得と保持

全タブのライブ画像を取得する API はありません。[captureVisibleTab](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-captureVisibleTab) は指定ウインドウの**現在表示中のタブ**を取得します。

この拡張では、ユーザーが一覧を開いた時、HTTP / HTTPS の現在タブを、一覧を重ねる**前**に1回だけ撮ります。別タブを自然に使った後、そこで一覧を開くとその画像も短時間保持されます。プレビュー収集のためにタブを自動巡回したり、裏のタブを選択したりしません。初めて開く一覧では現在タブの画像だけ、他は「プレビューなし」になるのが正常です。

- 最大8タブ、各画像は幅480px以下・JPEG・150KB以下。
- 最長2分のメモリ保持。session / local / sync storage、ファイルには画像を書きません。
- 2分経過、別 URL への移動／再読み込み、タブ終了・移動・置換、ワーカー停止で破棄。表示中の画像にも期限のタイマーを設定し、15秒ごとの再照合も行います。
- Chrome 内部ページ・ファイル・data URL・シークレットでは画像を取りません。取得できない画像はプレースホルダーで表示し、架空のスクリーンショットで補いません。
- 画像は静止画であり、現在の内容と異なる場合があります。キャプチャの前後にアクティブタブ・URL・ウインドウ・切替世代を照合し、途中で切り替わった結果は保持しません。
- Chrome の毎秒2回までの制限を避けるため、600ms以内の再取得を省略します。省略・取得失敗もプレースホルダーまたは有効な保存画像になります。

ページの内容自体に機密情報が表示されていれば、取得画像にも含まれ得ます。外部送信はしません。画像を全サイトから自動収集する権限は要求しません。

## 必要な権限（今回の増加分を含む）

| 権限 | 用途 |
| --- | --- |
| `tabs`（従来） | タイトル・URL・所属ウインドウの取得、確定時のタブ操作 |
| `storage`（従来） | MRU のタブ ID と順序を session storage に保存 |
| **`activeTab`（追加）** | 明示的な起動時の現在タブへの一時アクセス、表示領域の画像取得 |
| **`scripting`（追加）** | 起動した通常ページに UI を注入するため |

[activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab) と [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting) を組み合わせています。`host_permissions`、`<all_urls>`、常駐 `content_scripts`、nativeMessaging、debugger はありません。ただし **ユーザー操作時に注入するコンテンツスクリプトは使います**。ページ本文を収集する処理はありません。タイトルなどは `textContent` で表示します。画像を含む外部通信・外部フォント・外部ファビコン・分析 SDK はありません。CSP でも外部接続を禁止しています。

## 導入／更新（ユーザーが行う操作）

1. 利用する Chrome で `chrome://extensions` を開く。初めてなら Developer mode を自分で有効にし、「パッケージ化されていない拡張機能を読み込む」で上記 `extension` フォルダーを選ぶ。
2. 同じフォルダーを既に読み込んでいる場合は「更新／再読み込み」。権限の確認が表示されたら、上の用途を確認して自分で判断する。
3. 拡張をツールバーに固定する。
4. `chrome://extensions/shortcuts` で「最近使ったタブ」の一覧キーを確認する。変更する場合は入力欄をクリックし、希望するキーを押す。空欄なら競合などで割り当てられていない。
5. 通常の Web ページで Control + Q またはアイコンを押す。

通常プロフィールへの読み込み、Developer mode の変更、新規権限の許可、全サイトアクセス付与はこちらでは行っていません。ネイティブ補助・キーリマッパーは追加していません。組織管理で読み込みが禁止されている場合は、管理設定を変えず管理者へ確認してください。

## MRU と失敗時の動作

閲覧済み記録は画像とは独立した `storage.session.viewedTabsV2`（version とタブ ID の順序）です。フォーカス中の Chrome ウインドウで選択されているタブを、タブ切替・ウインドウのフォーカス変更・明示的な一覧起動時に照合して記録します。最後にフォーカスしたウインドウでも、現在 `focused` が false なら記録しません。視線やページ内容を判断するものではありません。

**初回導入・0.2以前からの更新・Chrome再起動・拡張再読み込み**で新形式の記録がない場合は、最初の観測時にフォーカス中の現在タブ1件だけを記録します。Chrome にフォーカスがなければ0件で開始します。他の既存タブを閲覧済みにはしません。旧 `mruV1` は削除し、lastAccessed やタブ位置から補完しません。導入前の閲覧状態は推定しません。

通常の背景タブ作成、非フォーカスウインドウでのアクティブタブ変更は、それだけでは閲覧済みになりません。そのウインドウを前面にすると現在タブを記録します。各ウインドウに属する閲覧済みタブを最後の表示順で絞り、先頭8件だけを表示します。閲覧済み状態は画像の2分失効では消えません。9件目以降は画面に出ませんが、タブを再表示すると先頭へ戻ります。

終了したタブは記録から削除。閲覧済みタブのウインドウ間移動では、状態を移動先に引き継ぎ、移動だけでは閲覧順を更新しません。タブ置換は元の閲覧済み状態を引き継ぎます。拡張の別ウインドウ自身は対象外です。履歴が0件なら案内を表示し、Enterや巡回は何もしません。

履歴更新と確定は直列実行します。一覧中の選択タブが消えたら選び直します。確定時に所属ウインドウと閲覧済み状態を再検査し、消失・移動していたら再選択できます。ワーカーだけの再起動では新形式の記録を復元し、0件の記録も維持します。画像は復元しません。開いている一覧のセッションが失われた時は Esc で閉じ、再度開いてください。

## 検証と構成

```sh
cd mru-tabs
npm test
npm run test:browser
```

Node.js 22 以降、追加パッケージ不要。ブラウザーテストは Chrome 156 の実験的 CDP を使うため、異なる版ではテスト側の更新が必要な場合があります。毎回新しい一時プロフィールで headless Chrome を起動し、127.0.0.1 の架空ページだけを使用、外部ホストの名前解決を遮断します。テスト終了後にブラウザーと一時プロフィールを削除します。通常のプロフィールや秘密情報は使いません。

[検証記録](VERIFICATION.md) を参照してください。実行ログ・実測JSON・画面画像は `npm run test:browser` の実行後、ローカルの `evidence/` に生成します。生成物はGit管理・リリースタグには含めません。

- `extension/model.js`, `controller.js`: MRU と直列 API 処理
- `extension/background.js`: action、セッション、メッセージ認証、イベント
- `extension/previews.js`: 縮小・枚数／有効期限管理
- `extension/view.js`: 共通カード UI、選択とフォーカス管理
- `extension/overlay.js`: 通常ページの closed Shadow DOM
- `extension/switcher.html`, `fallback.js`: 制限ページの別ウインドウ
- `test/`: ロジックテストと隔離実ブラウザーテスト

GitHub リポジトリは private です。タグ `v0.3.0` はこの版のコードを指します。GitHub Release の作成や Chrome ウェブストアへの公開は行いません。
